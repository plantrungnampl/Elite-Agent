# v4.2 End-to-End Contract Correction Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Correct the v4.1.1 cross-contract and end-to-end workflow gaps so read-only, write, learning, benchmark, and approval journeys have one coherent machine authority.

**Architecture:** Introduce versioned v4.2 machine contracts without mutating historical v4.1.1 inputs. `workflow-transitions.v2.json`, `cognitive-memory.v4.schema.json`, dedicated benchmark and actor-proof schemas, and `sqlite-v6.sql` become the production authority; `migrate-v5-to-v6.sql` upgrades existing stores by adding new authority tables and replacing drifted triggers. Legacy tables and schemas remain retained migration evidence only.

**Tech Stack:** Markdown, JSON Schema Draft 2020-12, SQLite STRICT tables/triggers, Python 3 validation, `jsonschema`.

## Global Constraints

- Preserve single-writer fencing, immutable evidence, exact-object approval, local-first authority, and fail-closed recovery.
- Agents never select their own workflow profile.
- Read-only completion must not enter implementation or Git finalization phases.
- Final Git approval binds one pre-created and verified immutable commit OID.
- Benchmark controls and treatment differences must be explicit and machine checked.
- No quality-improvement claim is permitted without completed benchmark evidence.
- Historical schemas remain immutable migration inputs and are not the current production authority.
