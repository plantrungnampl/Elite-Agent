# v4.3 Implementation and Product-Proof Baseline Design

**Status:** Approved by the user's request to apply the v4.2 review directly, self-review the result, and deliver a replacement ZIP.

## 1. Problem

v4.2 has strong safety, finalization, crash-consistency, and memory authority, but three defects block a clean implementation handoff:

1. normative protocol examples drift from `agent-protocol.v2.schema.json`;
2. workflow persistence permits raw phase changes that do not prove the declared event, profile route, or guard evidence;
3. benchmark and roadmap work prove memory treatments before proving that orchestration beats a single-agent baseline under comparable budgets.

The package also lacks a reconstructible provider/model run contract, an explicit independence model for High Assurance, controlled workflow-profile escalation, and machine-readable traceability with resolvable anchors.

## 2. Goals

1. Make every complete protocol frame in the normative protocol document schema-valid and backed by a canonical fixture.
2. Make workflow projection changes require an immutable accepted transition event, a declared rule, exact profile/outcome route, and required evidence/effect bindings.
3. Prevent `AwaitingPlanApproval -> Implementation` without an exact granted plan approval receipt.
4. Prevent Quick and non-Quick severe-objection routes from crossing.
5. Allow only receipt-backed monotonic escalation `Quick -> Standard -> HighAssurance`; never silently downgrade.
6. Define an immutable `RunConfiguration v1` that reconstructs provider, adapter, model, capabilities, data policy, budget, generation parameters, fallback, and independence group without storing credentials.
7. Represent degraded assurance explicitly when required independent groups or role separation cannot be met.
8. Add a separate equal-budget orchestration benchmark for single-agent, sampling, Quick, Standard, High Assurance, and heterogeneous arms.
9. Move a real read-only vertical slice and single-vs-multi proof ahead of memory breadth in the roadmap.
10. Add machine-readable requirement traceability with existing anchors, validation files, gates, milestones, and human-reviewed rationale.

## 3. Non-goals

- running a real provider or claiming runtime quality gains inside a design package;
- broad semantic-memory expansion, autonomous consolidation, remote retrieval, A2A production integration, marketplace, billing, or multi-user authority;
- making SQLite the sole implementation of all domain guards;
- silently changing historical v1-v6 contracts.

## 4. Authority model

The trusted application reducer validates a `WorkflowTransitionCommand`. In one SQLite transaction it:

1. resolves one versioned transition rule;
2. validates current phase, expected stream version, profile, outcome, event, guard evidence, actor/core identity, and required effects;
3. inserts immutable guard/effect bindings and an accepted transition event;
4. updates `task_workflow_authority` with that event ID and increments the stream version;
5. commits or rolls back the complete unit.

SQLite is the invariant boundary. It rejects projection changes without a matching accepted event and rejects known high-impact missing evidence, invalid profile routes, profile downgrade, and incomplete effect sets. Application code must not issue direct phase updates.

## 5. Versioned machine contracts

v4.3 introduces, without rewriting historical inputs:

- `schemas/sqlite-v7.sql` and `schemas/migrate-v6-to-v7.sql`;
- `schemas/workflow-transitions.v3.json`;
- `schemas/workflow-transition-command.v1.schema.json`;
- `schemas/run-configuration.v1.schema.json`;
- `schemas/assurance-degradation-receipt.v1.schema.json`;
- orchestration benchmark suite/run/comparison schemas;
- `schemas/product-traceability.v1.schema.json` plus a v4.3 instance;
- canonical protocol fixtures for every complete frame shown in `03-agent-protocol.md`.

## 6. Product sequencing

The roadmap becomes:

- **S0 Contract repair**;
- **S1 Real read-only vertical slice** with one supported real runtime;
- **S2 Multi-agent proof** under equal budgets;
- **S3 Mediated write**;
- **S4 Exact local commit**;
- **S5 Evidence retrieval**;
- **S6 Memory and learning**, unlocked only by measured lift.

Fake agents remain test fixtures, not the product milestone.

## 7. Acceptance

The package is accepted when:

- all historical suites remain green;
- every annotated complete protocol frame validates against the declared `$defs` target;
- transition tests reject raw updates, profile-route crossing, missing plan approval, missing required effects, profile downgrade, stale expected stream version, and event replay;
- valid representative read-only, Quick escalation, write-plan approval, workspace, and local-commit transitions pass;
- all new schemas compile and examples validate;
- machine traceability covers every current FR/NFR and all referenced anchors exist;
- no placeholders, broken local links, duplicate numbered headings, or stale current-authority references remain;
- checksums and a fresh-extraction validation pass.

Runtime model quality, adoption, containment on every Windows configuration, and real provider interoperability remain explicitly unproven until implementation evidence exists.
