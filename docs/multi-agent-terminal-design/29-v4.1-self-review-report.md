## 1. Review scope

This review checks whether the v4.1 package addresses the principal cognitive weaknesses identified in v4.0 without weakening authority, safety, migration, or audit guarantees.

## 3. Adversarial questions

### Can an old preference override a current instruction?

No. Fixed precedence assigns 600 to current instruction and 200 to explicit preference. A resolution receipt selecting a lower-ranked candidate is rejected.

### Can a vector result become state or active memory?

No. Retrieval remains derived. State and memory lifecycle require evidence and authority records.

### Can policy promote a harmful model-generated procedure?

Not without a passing shadow evaluation showing non-negative quality delta and zero new forbidden mistakes or unsupported claims. Explicit user override remains possible and auditable.

### Can a stale memory remain retrievable because nobody changed its status?

Not under v4.1 eligibility. Every typed invalidation rule requires a current passing evaluation before retrieval. Missing or expired evaluation excludes the memory even before a lifecycle worker marks it stale.

### Can utility automatically delete low-value memory?

No. Utility is a derived advisory projection. Retirement requires a retained consolidation action and normal lifecycle authority.

### Can adaptive budgeting hide arbitrary prompt construction?

No. The budget decision is immutable, bound to task/run/package, and its allocations must sum to the declared total.

## 4. Known limitations

- The SQLite contract proves structural guards, not retrieval quality.
- The bootstrap corpus is small and contract-focused.
- Shadow evaluation quality depends on benchmark and evaluator quality.
- Utility weight calibration is intentionally unspecified until runtime data exists.
- Existing v4.0 memory must be revalidated before it qualifies for v4.1 experience retrieval.
- Inferred preference remains risky and should stay disabled in the first release.

## 5. Recommendation

Proceed with a small read-only implementation slice. Do not implement broad cognitive automation until the four-arm benchmark demonstrates measurable benefit on representative repositories.

## 6. Executable validation evidence

The packaged validators prove the following on the final contract set:

- `30/30` v4.1 memory-utility checks pass;
- `19/19` v4.1 traceability checks pass;

- the full package regression suite passes `76/76` checks.
