# v3.2 Self-Review Hardening Plan

## Goal

Close newly discovered authority, evidence, replay, approval-consumption, and lifecycle gaps without expanding product scope.

## Review passes

1. Add failing counterexamples for every newly discovered unsafe operation.
2. Harden the SQLite clean-install contract until all counterexamples are rejected.
3. Expand package validation to cover every JSON schema/example, internal Markdown links, checksums, and stale assurance counts.
4. Re-read normative documents against the schema and remove contradictions.
5. Run a second adversarial pass against the hardened package and record remaining runtime-only gates honestly.

## Completion rule

The design is complete as a design baseline only when no known P0/P1 contract contradiction remains, all executable package checks pass from a clean extraction, and remaining gaps require implementation/runtime evidence rather than another missing contract.
