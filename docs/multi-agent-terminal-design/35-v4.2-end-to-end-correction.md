# v4.2 End-to-End Contract Correction

## Decision

v4.2 is a focused contract correction, not a wholesale redesign. It preserves
single-writer fencing, immutable evidence, exact-object approval, local-first
authority, fail-closed retrieval, and governed memory. It replaces the v4.1.1
contracts where complete user journeys or cross-contract round trips were
inconsistent.

## Corrected blockers

| Finding | Correction | Machine evidence |
|---|---|---|
| Read-only tasks could not finish | `ReadOnlyDeliverable` and `AwaitingDeliverableApproval -> Completed` | workflow v2 and completion package authority |
| Candidate-commit lifecycle contradicted itself | complete commit object is created before verification; `RefPromotion` is CAS only | workflow v2, final verification receipt, exact approval tuple |
| Terminal run status sets drifted | all six terminal statuses are accepted; all three nonterminal statuses are rejected | SQLite v6 triggers and terminal matrix |
| Benchmark treatment/control contract was contradictory | controls and declared treatment dimensions are separate | benchmark v3/run/comparison contracts |
| Benchmark runs did not bind actual inputs | revision, fixture, objective, budget, usage, policy, tools, model, prompt, evaluator, and rules are immutable fields | benchmark v6 tables and negative tests |
| Preference wire and storage shapes could not round-trip | canonical wire applicability and subject bindings are explicit | cognitive-memory v4 and memory wire/subject tables |
| Retrieval indeterminate was not serializable | indeterminate requires recovery receipt and last durable trace | cognitive-memory v4 example and schema test |
| Benchmark evidence lacked wire contracts | dedicated suite, run, result, comparison, and release schemas | Draft 2020-12 validation |
| Suite/case IDs could not retain logical identity | storage row IDs are separate from logical ID and version | benchmark suite/case version tables |
| Every task paid the same orchestration cost | trusted Quick, Standard, HighAssurance, and ReadOnlyResearch profiles | workflow v2 profile paths |
| Cognitive gates were not mapped to capability enablement | G11–G15 mappings are explicit | release-gate document checks |
| Actor/session proof was opaque | actor binding and one-time credential challenge lifecycle | actor schemas and SQLite replay rejection |
| Roadmap authority drift | SQLite v6 is the current clean-install contract | README and roadmap checks |
| Traceability covered only cognitive additions | all 51 FR/NFR requirements are mapped | full product traceability validator |

## Authority boundaries

- `task_workflow_authority` owns v4.2 profile, outcome, and phase. Legacy
  `tasks.phase` is retained as a v5 compatibility projection.
- Canonical memory wire fields live in `memory_wire_contracts_v2` and
  `memory_subject_bindings`. Legacy memory applicability is retained only for
  compatibility with v5 rows and triggers.
- New quality claims use benchmark v3 and v6 receipt tables. Legacy benchmark
  tables are historical evidence only.
- `RefPromotion` does not construct a commit and cannot change approved commit
  metadata. `ref_promotion_receipts` binds the granted approval consumption, exact
  repository/ref/old OID/new commit OID, and the CAS evidence artifact digest.

## Residual limitations

The executable v4.2 suite currently passes `96/96` checks, with clean/migrated SQLite parity at `451/451` objects. Passing schemas and journey tests proves contract coherence for the encoded
paths. It does not prove that models improve task outcomes, that all third-party
agents are contained on every Windows build, or that the product has market
adoption. Those remain runtime and product-validation questions.
